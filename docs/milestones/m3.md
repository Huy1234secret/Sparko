# M3 — Community

Complete locally; merged through [PR #4](https://github.com/Huy1234secret/Sparko/pull/4). Live Discord acceptance remains an external prerequisite.

## Delivered behavior

Typed workspaces replace the generic record view for every M3 module. Each settings page uses the shared community contract from `@sparko/messages/community-contracts`, the optimistic revision, idempotent save, server field errors placed on the matching control, saved-versus-applied status and a draft guard (`apps/web/src/features/config`).

- **R09 levels**: XP range, cooldown, curve with a live table that uses the domain formula, role and channel multipliers, exclusions and a level-up design. Staff see computed member levels and history and can make reasoned XP adjustments.
- **R11 reward roles**: stack or highest policy, per-level roles with hierarchy and privilege hints, and a member preview that only queues changes when applied.
- **R12 rank cards**: one browser-safe preference contract (`RankCardPreferencesSchema`) normalizes legacy values. `rankCardInput` derives identity, XP, level and rank from server state. Both the new `GET /levels/me/card.png` and Discord `/level` use it with the same renderer. With XP hidden, no bar or percentage is drawn (pixel-identical regardless of progress), and the maximum level is stated instead of an invented threshold. A member without recorded XP has no rank.
- **R10 crates**: drop and fallback channels, failure policy, exact weighted odds, manual and zero-reward preview drops, delivery state and errors, claims, and schedules with missed-run policy and cancellation.
- **R15 counting**: rules, milestones, reset design, per-channel status, and a confirmed, reasoned, revision-checked reset with history.
- **R16/R17 roles**: the role-menu builder offers only roles Sparko can grant, has exclusive groups and expiry, and reports field-addressed limit errors. Automatic join/boost roles explain roles above Sparko or with moderator permissions.
- **R19/R20 greetings**: welcome (channel and DM), leave and boost designs restricted to member-context templates, with Gateway coverage limits stated.
- **R31/R32 giveaways**: creation with eligibility and a local-time deadline sent as UTC; a list; detail with entries, draw history (algorithm, eligible entries, reason) and winners; end now; reasoned reroll. Members enter and claim from the portal.
- **R34/R35 suggestions and Q&A**: staff queues filter by state and record reasoned decisions or answers against the reviewed revision, keeping drafts on conflicts. Members submit private or public items, vote and accept answers.
- **R36 starboard**: settings and provenance history; deleted sources remain deleted.
- **R48 analytics**: a dense hourly series marks unobserved hours as breaks (never zero) and keeps observed quiet hours at zero. It flags partly observed hours, measures coverage only inside the requested window and shows voice time in participant-minutes. The page covers messages, joins, leaves and voice, with coverage, a per-day table, gap reasons, member count, module activity, CSV export of observations and gaps, and collection settings.
- **Member portal** (`/servers/:guildId/me`) was calling a nonexistent `/members/me`. It now shows authoritative level, rank and progress, the server-rendered card with its text alternative, card privacy, leaderboard opt-in, crates, giveaways and suggestions/questions.

## Backend corrections

- Community deliveries already used the validated publication pipeline. Role menus are now marked published only after Discord applies the message. Crate types, giveaways and role menus use their configured design with the required action row appended. Crates fall back to the first usable channel; with none, `skip` records a failed drop and `retry` retries. A blocked or dead send marks the record failed with its error. An applied send wakes the waiting check, so records open immediately instead of after a 30-second retry.
- One privileged-role mask (`@sparko/policy`) now serves both API preflight and worker delivery; the worker previously allowed Manage Messages and Mention Everyone. The role resource reports `assignable` and `privileged`.
- Every module config save checks each referenced channel and role at any depth and returns field paths. The web config contract accepts prerequisites reported with their path; previously any unmet prerequisite broke the settings page.
- New staff reads: computed member levels, member XP history, crate history, counting resets, all role menus with delivery state, and giveaway detail with entries, draws and winners.

## Manual smoke and remaining boundaries

1. Enable leveling, change the curve and save. Confirm the table and saved revision.
2. Open the member portal. Confirm the card matches `/level`, then hide XP and confirm the bar disappears.
3. Enable giveaways, create one and confirm it opens only after the message posts. Enter once.
4. Create a role menu with an ordinary role below Sparko. Confirm moderator roles are not offered.
5. Deny Sparko Send Messages in the crate channel with a fallback configured and drop a crate.
6. Turn analytics on and confirm unobserved hours show as gaps.

Live Discord Gateway events (joins, messages, reactions, voice), role assignment, DMs and component interactions still require a configured application and test guild. Message XP, counting and starboard need actual Gateway observation; these tests exercise the domain and worker with controlled inputs. Rank cards do not render avatars or uploaded backgrounds (the renderer supports only clean local bytes, and no avatar source is wired). Delayed author-authority rechecks for community publications follow the existing publication path.
