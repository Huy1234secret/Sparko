# M7/M8 — Economy and social workflows

Complete locally. Delivered through the M7/M8 milestone PR (see progress.md for the PR and CI run). Live Discord role delivery and live provider polling remain external prerequisites.

## Delivered behavior

**Composite read models (R51–R56, R67)**

Member reads now return purpose-built views instead of raw records, joining the item definitions they refer to. No view exposes another member's records.

- `GET /economy/me`:
  - exact balance and currency name
  - which economy modules the member can use, decided by the same gate as the routes
  - transfer limits
  - reward amounts, today's earnings against the cap, exclusion state, and when daily and work rewards are next ready
  - recent rewards
- `GET /inventory/me`: held items with names, kind, rarity and tradeability, plus the member's orders with delivery or refund detail.
- `GET /collections`:
  - the active collectible catalogue with owned counts
  - recipes with each ingredient's name and how many the member holds
  - hunt usage and next-ready time
  - published drop chances
- `GET /trades/me` and `GET /auctions`: whether each trade was sent or received, named assets, and the member's position in each auction (seller, leading, has bids).
- `GET /lotteries`: each draw with its pot and sold tickets, but only the caller's own ticket count.

**Trivia reload recovery (R56)**

- New `GET /games/me` returns:
  - the member's open question, without its answer
  - recent results, with the answer revealed only once a session is final
  - plays left and when the next play is allowed
- A member who reloads mid-question can still answer it. Before this, the session id was lost and the cooldown blocked a new game.

**Staff order queue (R53)**

- New `GET /shop/orders` (`economy.manage`) lists orders. It shows undelivered role orders by default (waiting, delivering, failed), with filters for delivered, refunded and all.
- Each row shows the member, item, role, price, delivery error and refund detail.
- **Refunds:**
  - Refunds need a reason.
  - They are offered only for waiting or failed orders. An order mid-delivery explains that it is waiting for Discord.
  - The existing refund-once rule is unchanged.

**Member economy portal**

`/servers/:guildId/economy` is linked from the member profile and the sidebar. Its tabs follow the modules the server has on:

- **Wallet:**
  - daily and work claims with next-ready times
  - transfers that show the limit and fee
  - ledger history in member language
- **Shop:** price, stock, role and unique notes, and affordability.
- **Inventory:** use consumables and see your orders.
- **Trading:**
  - Propose trades: offer from tradeable inventory, ask from the catalogue.
  - Accept, decline or cancel trades.
  - Auctions: bid, list items, and cancel before the first bid.
- **Collection:** hunt with published odds, a collection grid, and crafting with ingredient counts.
- **Trivia:** a live countdown; the open question survives a reload.
- **Lottery:** an explicit virtual-only opt-in for every purchase; only your own tickets are shown.
- **Standing:** the season leaderboard (public profiles only), achievements with progress and claim, and reputation with commendations.

Repeatable actions (claim, hunt, play, buy) reuse their idempotency key only until the server confirms them, so a retry never pays or charges twice and the next action is new.

**Staff economy pages**

All of these replace the generic record pages with typed pages that need no JSON.

- **Economy (R51):**
  - Ledger health, rebuilt from the ledger.
  - Audited grants that need a reason.
  - Currency name and limits.
- **Daily & work rewards (R52):**
  - Now in navigation.
  - Amounts and cooldowns are entered in hours or minutes.
  - Settings cover the daily cap, role multipliers as percentages, the maximum multiplier and excluded roles.
- **Shop (R53):**
  - The item editor:
    - Role items: the role is chosen from a list that disables privileged roles and roles above Sparko. Unique and untradeable are enforced.
    - Consumables: a "using one pays" reward.
    - Optional stock limit and role requirement.
  - Stock changes need a reason and the current revision.
  - The order queue, with an attention count.
- **Trades & auctions (R54):** an auctions overview, the longest duration and the highest bid.
- **Collections (R55):** recipes, and hunt drops with live chance percentages.
- **Trivia (R56):** a question bank with the right answer marked, editing by question ID, and play limits and reward settings.
- **Lottery (R67):** a required virtual-only acknowledgement, published draws, and cancel-and-refund with a recorded reason.
- **Reputation (R68):** daily, pair and membership limits.
- **Seasons (R13):** start a season, end it early with a reason, and view each season's public leaderboard.
- **Achievements (R14):** metric, item and season targets, reward, XP and badge.

**Social alerts and provider panels (R47, R64, R65, R69)**

- **Social & RSS alerts:**
  - **Sources:** each shows when it was last checked and today's check and post budget. Staff can check one now or turn it off.
  - **New source:** a form per provider:
    - GitHub owner and repository
    - RSS feed URL
    - YouTube channel ID
    - Twitch username
  - **Recent items:** each item's outcome (posted, posting, existing item not posted, skipped at the daily limit).
  - **Settings.**
  - `GET /social/sources` now also returns last-poll times and budget usage.
- **Provider status panel:** shared by the social, music and AI pages.
  - It says whether the operator has set up each provider, but never names configuration values or secrets.
  - It states that nothing has been confirmed live.
  - A delegated manager without settings access gets an explanation instead of an error.
- **External events:** integrations are created with a 64-character signing secret generated in the browser. It is shown once with the endpoint and signature scheme, then stored encrypted. Integrations can be revoked.
- **Music:** settings, with a clear warning that no voice playback runtime exists.
- **AI assistance:**
  - a disclosure of what is shared
  - a required acknowledgement and per-purpose opt-in
  - limits and retention

## Evidence

Local run on Node 24.19.0, with disposable PostgreSQL 16 and Redis 7:

- typecheck, lint, format and build pass, including the browser-boundary check.
- **266** unit tests, **167** PostgreSQL integration tests and **23** browser journeys pass.
- No schema change in this milestone.

New focused coverage:

**Domain (PostgreSQL)**

- A trivia question opened by one member is recovered after a reload without its answer, and another member never sees it. After answering, the result reveals the answer and the selected choice.
- Inventory, collections and trades name their items:
  - Trades are marked sent or received.
  - A third member sees no trades.
- Lottery views show the shared pot but only the caller's tickets.
- The staff queue:
  - It lists a failed role order with its error.
  - Members are refused.
  - Once refunded, the order leaves the attention list and appears under refunded with its reason.
- The overview reports module gates, the next daily time and recent rewards.
- Social source view: last-poll time and budget usage, refused to plain members.

**Web**

- Only enabled modules become tabs, and balances are exact.
- A ready reward is claimed, while a cooling one stays disabled with its time.
- An open trivia question is resumed.
- The refund queue needs a reason and offers no refund mid-delivery.
- Role items are forced unique and untradeable, and privileged roles are disabled.
- The provider panel never names secrets or claims live checks.
- Delegated managers get an explanation of why status isn't shown.
- Music warns that no runtime exists.
- A webhook secret is generated in the browser and shown once.

**Browser journeys** (`tests/e2e/economy.spec.ts`)

- Staff do all of this through typed forms:
  - turn on the economy, rewards, shop and trivia
  - add a limited item
  - grant funds with a reason
  - add a question
- A member then:
  - claims the daily reward and sees the next-ready time
  - buys the item, which reduces the stock
  - sees it in their inventory and orders
  - starts trivia, reloads, answers the same question and sees the result
- The ledger still balances.
- Staff add a GitHub release source:
  - The provider panel shows GitHub ready and YouTube needing operator setup.
  - A check is requested.
  - The source is turned off.
- The browser test worker skips provider polls so journeys never reach real third-party hosts.

## Setup

No migrations and no new environment settings. Provider settings in `docs/providers.md` still decide which social providers can be checked.

## Remaining boundaries

- Live Discord role delivery, hierarchy failure and ambiguous timeouts for shop role items.
- Live provider polling (RSS hosts, YouTube, Twitch, GitHub limits), AI generation and a voice playback runtime.
- A member and staff AI request UI.
- Opt-in multi-server rollout (R61) and configuration backups (R50).
- Display names instead of Discord user IDs in trades, auctions, leaderboards and orders.
- A real-time trivia countdown is client-side; the server's expiry is authoritative.
