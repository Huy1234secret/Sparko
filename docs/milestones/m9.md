# M9: Configuration tools, quality matrix and deployment plan

Complete locally. Delivered through the M9 milestone PR (see progress.md for the PR and CI run). Production deployment has not happened; it needs the authorizations listed in [the deployment plan](../deployment-plan.md).

## Delivered behavior

**Configuration backups (R50)**

- **New routes:** `GET/POST /guilds/:guildId/backups`, `POST …/backups/import`, `GET …/backups/:id` (the downloadable file), and `POST …/backups/:id/preview`, `/restore` and `/delete`. All of them need `config.manage`.
- **Saving:**
  - A backup holds module settings only.
  - Access policy, plan and billing, privacy, music, AI consent, external events, public widgets and the multi-server opt-in are never included, restored or rolled out. Each server decides those directly.
  - 25 backups are kept per server.
- **Importing:**
  - An imported file is checked against the same schemas as the settings editor before it is stored, and each problem is named by module and setting.
- **Restoring:**
  - A restore previews what would change.
  - It lists the channels and roles this server lacks, and lets staff match each one to a channel or role here.
  - It then writes only the ticked modules, under the revisions shown in the preview, after the editor's schema and Discord reference checks.
  - A change made after the preview restores nothing.
  - Retries replay instead of writing twice.
- **Page:** Server settings › Configuration backups lets staff save, import, download, restore and delete backups.

**Multi-server tools (R61)**

- **Opt-in:** each server opts in separately: comparison, and rollout into that server.
- **Checks before any read:** every server named in a request is authorized afresh and must have Plus and the module on. The source server's settings are not read until that passes.
- **Preview:** per target server. It remaps channels and roles and names anything still missing.
- **Rollout (`POST /multi-server/rollout`):**
  - It writes each opted-in target atomically on its own, under the previewed revisions.
  - Each server's result is reported: applied, already the same, rollout not allowed, changed since preview, or needs changes.
  - One server failing never undoes another.
- **Page:** Server settings › Multi-server tools picks servers and modules, previews, matches resources and shows results.
- **Shared code:** the settings editor, backups and rollout now share one reference finder, remapper and revision-checked writer (`packages/domain/src/config-tools.ts`).

**Public widgets (R70)**

- Server settings › Public widgets publishes the status widget and the XP leaderboard separately. A clear public-exposure warning is shown, and the Links tab checks each public link live.

## Evidence

Local run on Node 24.19.0, with disposable PostgreSQL 16 and Redis 7:

- typecheck, lint, format and build pass, including the browser-boundary check.
- **274** unit tests, **173** PostgreSQL integration tests and **29** browser journeys pass.
- No schema change in this milestone.

New focused coverage:

**API (PostgreSQL)**, `apps/api/src/config-tools.integration.test.ts`:

- Snapshots leave out protected modules, and members are refused.
- A restore after a newer save is refused, and nothing is written. A retry replays, the audit records one restore, and the configuration revision advances once.
- Imports from another server:
  - A tampered file is rejected and named by setting.
  - A restore without remapping names each missing channel and role, and the remapped restore writes the target's own IDs.
- The backup limit holds, and deleting a backup makes room.
- Rollout:
  - It needs Plus on every server, naming the server that lacks it.
  - Protected modules are excluded.
  - It writes remapped settings once. It then reports "unchanged", and a stale preview is reported as a conflict.
  - A server that has not opted in is refused. A server that allows comparison only is reported and not written.

**Domain:** references at any depth skip message documents, remapping keeps unmapped IDs, comparison names missing resources, and protected modules are listed.

**Web:**

- The protected-settings notice is shown, and naming a backup saves it.
- A non-backup file is refused before upload.
- A restore stays blocked until every missing channel is matched and previewed again, then sends the previewed revisions and the remap.
- Rollout skips servers that allow comparison only and reports each result.

**Browser:**

- Back up, download and check the file, change a setting, restore, and see the old value.
- A widget returns 404 until it is published and then exposes only its documented fields.
- The accessibility matrix.
