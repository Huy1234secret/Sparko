# M2 — Message platform

Complete locally; delivered through the M2 milestone PR (see progress.md for the PR and CI run). Live Discord acceptance remains an external prerequisite.

## Delivered behavior

R05/R06/R07 use one validated, browser-safe message document across Studio, API, BotRuntime and durable worker. Studio edits V2 containers and nested blocks, section thumbnails/buttons/actions, gallery items, traditional embed fields/links/UTC timestamps and custom emoji fallbacks. Undo/redo, keyboard ordering, schema-versioned import/export, token context/budgets and desktop/mobile previews remain part of the canonical design workflow.

Draft saving and autosave use optimistic revisions. Named immutable version history supports preview, duplication and restore by appending a new version. Loading history keeps the prior unsaved draft; delayed responses cannot rebind another editor/server. Restoring a design does not post or rewrite a live publication.

Publication inventory distinguishes saved business state from actual delivery status and sanitized errors. Compatible edits preserve control identity; mode or action changes require reviewed replacement. Reconciliation observes matching, missing, conflicting and unidentified Discord messages without sending a replacement. Archive/replacement cleanup must preserve visible V2 content while revoking issued controls, including recovery of an accepted send whose response was lost.

Persistent controls resolve tenant/publication/action snapshots and recheck current actor authority. Application and ticket forms span multiple actor-bound persisted modal steps, survive BotRuntime recreation, validate immutable choices and support cancellation/expiry. Republished forms, revoked controls, invented choices and lost eligibility cannot submit stale answers.

R08's owned animation library, reduced-motion/static fallbacks and valid Discord equivalents are shared with the existing asset package. Uploaded media is normalized to bounded PNG bytes before use. Public sharing requires explicit consent; private media stays owner/tenant scoped. API and delivery check actual channel overwrites, attachment permissions and fresh custom emoji availability. Missing emoji uses its configured Unicode fallback or a field-level error.

## Evidence and setup

The fifth native migration, `202610110005_template_version_labels`, adds optional bounded names to immutable template versions. Generate the native client and apply the full ordered chain to an explicitly disposable database using docs/setup.md.

Focused PostgreSQL checks cover template snapshot/revision/tenant invariants, resource permissions/media scope, long forms over restart/cancellation/concurrent final submit, delivery failures and external reconciliation. UI regressions cover version/draft safety and editor controls.

Worker review corrections (archive preserving V2 display, lost-response recovery from durable evidence, empty-content embed edits, strict drift comparison) are verified by 24 worker PostgreSQL and 11 unit cases. A serializable-snapshot idempotency race (a waiter's snapshot predating the advisory lock could miss a just-committed operation key) is retried on the unique violation with proportional jitter.

Web services now preserve API `fieldErrors` and `retryable` on `ApiError`. Forms place server field errors beside their controls (focus first, summarise unknown paths, `aria-invalid`/`aria-describedby`), and offer a same-key retry only for transient failures. The ticket settings route names the unavailable channel or role field. `/messages/templates` and `/messages/publications` focus their Studio sections; mobile inspector cards span the column.

Combined result on the delivered source (local Node 24.19.0; PostgreSQL 16 because Docker Hub pulls were rate-limited, CI uses 17.6): typecheck, lint, format, build and browser-boundary pass; **165** unit tests; **135** PostgreSQL integration tests in 13 files from an empty disposable schema with all five migrations; **7** browser journeys. Production Compose validation and both images run in CI.

Seven browser journeys combine the original identity/ticket/mobile/publication/media paths with nested/accessory/gallery/UTC editing, named history/duplicate/restore/draft preservation, emoji fallback and actual worker recovery. They use real API/authentication/database/BotRuntime/outbox code; only Discord's external boundary is controlled.

## Manual smoke and remaining boundaries

Sign in, open a server's Studio, edit a nested V2 design and section accessory, then save a named version. Edit/save another version, preview and restore the first, and duplicate it. Confirm the original snapshots remain and no draft operation posts a message. Publish to an authorized channel, make a compatible edit, review a control/mode replacement, and archive the old publication. Remove or change the original Discord message, reconcile, and confirm a new message requires explicit replacement.

Publish an application/ticket form with more than five fields, recreate the bot process between steps, complete or cancel it, and confirm final authorization/version checks. Revoke the source control or eligibility and verify refusal. Upload bounded media, choose public sharing deliberately, and verify actual attachment bytes and private-download scope.

Live Discord OAuth, V2/embed edits, modal StringSelect acceptance, emoji availability and permission behavior still require a configured authorized application and test guild. This milestone does not claim live provider success or production cutover. M3 continues typed community workflows and their combined Gateway/job/UI acceptance; later milestone gaps remain in progress.md.
