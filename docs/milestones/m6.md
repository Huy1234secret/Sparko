# M6 — Feature gates, plans, support and owner operations

Complete locally. Delivered through the M6 milestone PR (see progress.md for the PR and CI run). Live provider and Discord acceptance remain external prerequisites.

## Delivered behavior

**One feature gate (R04, R59, R60)**

- Sparko now tracks the gates from spec §14.2 separately:
  - **enabled:** the server's own switch.
  - **owner allowed:** a staff pause, stored in the new `FeaturePolicy` table (migration `202610120007_feature_policy`), so a server's save can never clear it.
  - **plan entitled:** for example, multi-server tools need Plus.
- `featureGate`, `gateError` and `featureActive` in `packages/domain/src/core.ts` are the single check, used by:
  - every HTTP route (`ctx.requireFeature`)
  - Gateway ingestion: safety, auto replies, sticky messages, temporary voice, invite tracking and rewards, and every community module
  - workflow start and advancement
  - the worker's safety and auto-moderation effects
- New error codes: `FEATURE_BLOCKED` (403, carrying the staff reason) and `PLAN_REQUIRED` (403).
- Cleanup deliberately skips the gate, so pausing a module or losing Plus never strands data. This covers role expiry, invite-reward reversal, refunds, settlement, retention and privacy maintenance.
- Feature config reads include the gate and the plan's limits. Settings pages show "Paused by Sparko staff" with the reason, or "Needs the Plus plan", next to the server's own switch, which stays as the server set it.

**Uniform plan limits (R60)**

| Limit                   | Free   | Plus    |
| ----------------------- | ------ | ------- |
| Saved message designs   | 10     | 100     |
| Image library           | 10 MB  | 100 MB  |
| Steps in one workflow   | 10     | 25      |
| Ticket transcripts kept | 7 days | 30 days |
| Multi-server tools      | no     | yes     |

- `requirePlanRoom` refuses new work past a limit with `PLAN_LIMIT`, naming the limit and plan.
- After a downgrade, everything is kept: work already over a limit stays usable, and only new work past the limit is refused.
- Transcript retention is fixed from the plan at capture time.
- The workflow builder stops adding steps at the plan's limit.

**Delegated resource discovery (R04)**

- Channel, role and emoji listing is now open to any delegated staff permission (tickets, moderation, forms, reports, appeals, analytics, economy, access and others). Plain members still cannot list them.
- Writes still check their own permission.

**Plans and billing (R60)**

- The server "Plan & billing" page shows:
  - the current plan and a Free vs Plus table of the real limits
  - what happens on downgrade
  - the subscription and staff-grant history
  - checkout, but only when the provider is configured, with "Continue to secure checkout" once the provider issues a session
- `/account/billing`, the Stripe return target, lists the servers you manage. It explains that a plan changes only when the provider confirms payment.

**Owner operations (R59)**

- The console shows only the sections the operator's permissions allow:
  - health (`diagnostics.read`)
  - servers (`fleet.read`)
  - jobs (`diagnostics.read`)
  - support queue (`support.read`)
  - operator access (bootstrap owners)
- A support-only operator no longer hits a diagnostics error. The sidebar entry appears for any operator permission.
- **Servers:**
  - search
  - the plan and its history
  - staff Plus grants and revocations (`entitlements.manage`)
  - per-module pause and resume with a reason the server sees
- New routes:
  - `GET /owner/guilds/:guildId`
  - `PUT /owner/guilds/:guildId/features/:featureId/policy`
  - `POST /owner/guilds/:guildId/entitlements`
  - `POST .../entitlements/:id/revoke`
- Every change is a guild-audited operation with a reason and a revision check.
- Staff grants expire on their own. Provider subscriptions change only through verified provider events.
- **Jobs:** readable rows and an audited retry form. Unknown outcomes are labelled and stay ineligible for retry.
- **Operator access:** grant, change and remove expiring global permissions.

**Product support (R58)**

- **Lifecycle:** open, waiting on the member, resolved, closed.
  - A staff reply waits on the member; a member reply returns the request to support.
  - Members close and reopen their own requests. Staff with `support.reply` set any state. A closed request takes no messages.
- **Screenshots** (migration `202610120008_support_attachments`):
  - Up to three per message and ten per request.
  - Re-encoded as metadata-free PNG and stored with the request, so they are deleted with it.
  - Operation receipts keep only a content hash.
  - Downloads are limited to the requester or support readers, sent as attachments with `nosniff`.
- The member page is an inbox with a readable thread, replies, screenshots, and close or reopen. The staff queue filters by status and is read-only without `support.reply`.

**Privacy exports (R62)**

- `POST /account/privacy/export` takes `kind`:
  - `full` (default)
  - `support`: product support conversations only
  - `servers`: tickets and personal records kept by the servers you use
- Exports list attachment details, never image bytes. The privacy page offers the choice and labels each export.

## Evidence

Local run on Node 24.19.0, with disposable PostgreSQL 16 and Redis 7:

- typecheck, lint, format and build pass, including the prerender and browser-boundary checks.
- **257** unit tests, **162** PostgreSQL integration tests and **21** browser journeys pass.

New focused coverage:

**Domain (PostgreSQL)**

- A staff pause stops new HTTP and Gateway work (auto replies). Invite-reward reversal still runs.
- A running workflow stops at its next step when paused.
- Multi-server tools need Plus. A staff grant enables them, and expiry is read from the instant itself.
- Saved designs stop at 10 on Free. Plus allows more, and a downgrade keeps all eleven while refusing new ones.
- Workflows over 10 steps are refused on Free.

**API (PostgreSQL)**

- `fleet.read` can read but not change. Policy changes need `entitlements.manage`, a reason and the current revision.
- The config read shows the pause. The change is audited.
- A staff Plus grant and its revocation.
- Delegated `tickets.manage` can list channels, plain members cannot, and the access ends when the grant is removed.
- Screenshot privacy, SVG refusal, the status lifecycle, a closed request refusing replies, and support-only exports without image bytes.

**Web**

- A support-only operator sees only the support queue, read-only, with no health request.
- Staff replies.
- Pausing requires a reason.
- The billing page's real limits and honest checkout state.
- The settings pause notice.
- The member inbox thread with screenshot links.

**Browser journeys** (`tests/e2e/owner-account.spec.ts`)

- An owner pauses auto replies with a reason. The server's settings show the reason with its switch unchanged, and creating a reply is refused. Then it is resumed, and a staff Plus grant appears on the server's billing page.
- A member sends a support request with a real screenshot, which is re-encoded and served only to them. Staff reply and the request waits on the member. The member sees the reply, closes the request (replying is then gone) and requests a support-only export.

## Setup

- Apply migrations `0007` and `0008` to an explicitly disposable database first, following `docs/setup.md`.
- No new environment settings. Checkout stays unavailable until the Stripe settings in `docs/providers.md` are configured.

## Remaining boundaries

The following still need provider sandbox and live credentials:

- Real checkout, callbacks, refunds and disputes.
- Moving a subscription between servers. Not offered; a staff grant can cover a support case.
- Support notifications (email or DM) about staff replies. Replies are visible in the inbox only.
- A scoped diagnostic export requested by support.
- Usage and quota dashboards in the owner console beyond the plan limits.
