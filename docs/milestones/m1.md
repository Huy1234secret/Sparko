# M1 — Identity and the first complete workflow

M1 completes the locally verified identity/setup/ticket slice. Its source was integrated with the shared M0 baseline; this milestone records the acceptance boundary and distinguishes local evidence from the required later live Discord check.

## Delivered behavior

A user signs in through OAuth state/callback/session handling, selects an authorized installed server, previews/applies support setup, and saves ticket settings with staff/category/topic/question selections. Message Studio previews and publishes the panel. Saved/pending status remains visible while the worker is paused, then reflects durable delivery.

A panel interaction reaches the actual BotRuntime, presents configured ticket questions and persists the answers. Recreating BotRuntime before the click does not invalidate issued controls. The worker creates the private support resource; the dashboard lists it. Staff claim the ticket and close it with a reason, then download a retained private transcript through a fresh authorized API request. Required capture failure keeps the Discord resource for recovery.

Shared contracts enforce guild scope, CSRF, idempotency and optimistic revisions. Historical ticket access uses that ticket's persisted staff snapshot; acquiring a newly configured staff role does not reveal prior private answers. Read-only delegation can read permitted records/transcripts without claiming or modifying them.

## Evidence

- `pnpm test:e2e`: four tests pass. The identity/setup/ticket test exercises actual OAuth/session cookies, API, PostgreSQL, BotRuntime recreation, modal answers, worker, claim, keyboard closure and authorized transcript JSON download.
- PostgreSQL API/security/domain/bot/worker regressions pass within the 104-test root integration suite: OAuth replay/logout revocation, CSRF/cross-guild denial, idempotency conflicts/replays, stale configuration, duplicate ticket creation, concurrent claim, revoked controls, scoped transcript access and capture/lifecycle races.
- Whole-workspace TypeScript, lint, format and build pass; 128 unit tests pass. Desktop and 390px mobile screenshots and keyboard/reduced-motion behavior were inspected.

Only the external Discord authorization/API boundary is controlled. Persistence, handlers and durable effects are the real application code. A live application/server must separately verify OAuth exchange, permissions/hierarchy, panel/modal acceptance, private-channel visibility and transcript capture. No live success is claimed.

## Reproduce and continue

Follow docs/setup.md for explicit disposable services; run native generation/migrations and the root verification scripts. `pnpm test:e2e` starts its own test API/browser server against the separate named browser database. Its test-only controls and FakeRest are excluded from production entrypoints.

For live smoke, register the documented callback, securely configure Discord credentials and install the bot in an authorized test guild. Repeat login, support setup, publish, configured modal, private-channel creation, claim, close and private transcript download. Do not treat this local acceptance as production cutover approval.
