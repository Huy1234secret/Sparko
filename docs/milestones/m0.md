# M0 — Fresh foundation

This milestone establishes a runnable new Sparko workspace with persistent service boundaries, strict shared contracts, a native migration chain and reproducible verification. It does not mark the partially implemented M1–M9 modules complete.

## Delivered behavior

- New pnpm/TypeScript monorepo: React/Vite web, Fastify API, Discord bot, durable PostgreSQL outbox worker, shared contracts/policy/message/rendering/assets packages. No legacy application dependency.
- Original yellow primitives, theme and reduced-motion controls; public React pages prerender with canonical metadata, sitemap and CSP hashes.
- Authenticated tenant boundaries and idempotent operations; serialized guild mutations retry rolled-back PostgreSQL query/commit conflicts with bounded backoff. External effects use fenced leases and remain distinguishable from saved state.
- Native PostgreSQL schema migrations include balanced immutable ledger constraints and OAuth refresh fencing. No external API calls are performed while holding those refresh/storage/delivery transactions.
- Actual root verification scripts, disposable PostgreSQL/Redis Compose, explicit development-only seed, CI and browser import checks.
- Non-root production containers/proxy, restricted backups, checksummed disposable restore and documented setup/deployment/operations.

## Local evidence

Clean frozen installation, native client generation and four ordered migrations passed. Root strict TypeScript and ESLint passed. Unit/compiler/rendering/assets tests passed; final full counts and browser results are recorded in progress.md.

Production images built. No production deployment was performed. PostgreSQL 17 backup/restore passed checksum, schema and ledger validation into a separate disposable database. Test-target, seed-mode and corrupted-archive rejection guards passed.

Local workflow tests use the actual OAuth/session/API/database/BotRuntime/worker with a controlled Discord boundary. No live Discord acceptance, provider sandbox success or domain cutover is claimed.

## Reproduce

Follow README and docs/setup.md: use Node 24.19.0 and pnpm 11.25.0; install with the frozen lockfile; generate the client; start disposable services; run the native migrations and root checks. Tests require explicit TEST_DATABASE_URL and TEST_REDIS_URL; production DATABASE_URL is never a test fallback. Never reset an operator database with the test runner.

For a manual smoke, start the normal API and web, open public pages, inspect the explicit missing-Discord login/setup state, and run tools/smoke.ts against the chosen origin. A configured Discord application and test guild are required for the separate live login/install/publish/ticket smoke. Follow docs/deployment.md and docs/operations.md for container and restore procedures.
